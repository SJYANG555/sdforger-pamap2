\begin{frame}{Goal and Evaluation Protocol}
\begin{itemize}
  \item Task: generate PAMAP2 sensor windows for two activities: \textbf{walking} and \textbf{running}.
  \item Model: \textbf{Gemma2-2B + LoRA/PEFT}; base model frozen; LoRA applied to the last 30\% layers.
  \item Window setup: 256 samples, stride 128.
  \item Evaluation:
  \begin{itemize}
    \item \textbf{Generation validity}: valid generated windows after parsing/filtering.
    \item \textbf{Class balance}: generated running vs walking counts.
    \item \textbf{Similarity}: ED and DTW, lower is better.
    \item \textbf{Utility}: Random Forest HAR accuracy using synthetic-only and real+synthetic training.
  \end{itemize}
\end{itemize}
\end{frame}

\begin{frame}{Improvement Roadmap}
\begin{enumerate}
  \item Reduce activities from five PAMAP2 classes to \textbf{walking/running}.
  \item Sensor selection:
  \begin{itemize}
    \item full body, hand, chest
    \item acceleration-only and gyroscope-only variants
  \end{itemize}
  \item Epoch scaling: compare \textbf{5, 10, 20 epochs}.
  \item Embedding dimension test: ICA8 was tested but did not show consistent benefit.
  \item Statistical prompt: add per-window statistical summaries to the text prompt.
  \item Final combined test: \textbf{statistics prompt + epoch scaling}.
\end{enumerate}
\end{frame}

\begin{frame}{Conclusions}
\begin{itemize}
  \item Reducing PAMAP2 to \textbf{walking/running} made the generation task more stable.
  \item Sensor choice matters:
  \begin{itemize}
    \item \textbf{hand} is best for utility.
    \item \textbf{chest gyro} is best for waveform similarity.
  \end{itemize}
  \item More epochs alone are not sufficient; 10/20 epochs can reduce validity or utility.
  \item ICA8 did not provide a consistent improvement and was not continued.
  \item \textbf{Statistical prompts are the most useful improvement}:
  \begin{itemize}
    \item hand + stats improves utility and validity.
    \item chest gyro + stats preserves strong similarity and improves utility relative to baseline.
  \end{itemize}
  \item Main insight: fidelity metrics and downstream utility measure different aspects of synthetic quality.
\end{itemize}
\end{frame}

\begin{frame}{Backup: Metric Interpretation}
\begin{itemize}
  \item \textbf{Valid generated count}: how many generated candidates survive parsing, deduplication, and norm filtering.
  \item \textbf{Running/Walking count}: checks whether accuracy is inflated by class imbalance.
  \item \textbf{ED}: Euclidean distance between real and synthetic prototype windows.
  \item \textbf{DTW}: temporal alignment distance between real and synthetic prototype windows.
  \item \textbf{ED/real, DTW/real}: normalized against a real-vs-real random split baseline.
  \item \textbf{Synthetic-only utility}: train classifier on synthetic data only, test on real data.
  \item \textbf{Real+synthetic utility}: train on real plus synthetic, test on real data.
\end{itemize}
\end{frame}
